# Known Issues

Problems found during the project review that still need to be resolved.

## 1. AI response overwrites user-entered data

The `CareTips` schema in `lib/aiHelpers.ts` includes `name` and `botanicalName`. The `addPlant` store action merges the whole AI response into the plant via `updatePlant`, so the user-entered `name` is replaced by the model's value.

Expected: only AI-generated fields are merged; user-entered fields are preserved.

## 2. `max_output_tokens: 200` is likely too low

The structured JSON with a `careTips` array may be truncated, causing parsing to fail and the helper to return `null`. Not verified with a real API call.

## 3. Unused fields in the plant model

`notes`, `imageUrl`, and `lastWatered` exist in `TPlant`, but there is no UI to set them. `imageUrl` is not used anywhere — the detail page loads the image from `/img/${plant.type}.png`.

## 4. Limited test coverage

Vitest is set up and covers the AI route, the AI helper, and `updatePlant`. The form schema, the `addPlant` flow, and UI components are not tested yet.

## 5. UI text language and typo on the plant detail page

`app/myGarden/[id]/page.tsx`:

- Line 13: Ukrainian UI text `Рослину не знайдено 🌱` — UI text should be in English.
- Line 134: typo `Last watred`.

## 6. Minor UI bugs

- `app/myGarden/[id]/page.tsx`: `botanicalName` is generated by AI, but the page shows the hardcoded placeholder `plant's scientific name`.
- `app/myGarden/[id]/page.tsx`: each care tip has its last character removed (`tip.split("").slice(0, -1)`).
- `app/myGarden/page.tsx`: table rows use `key={plant.name}` instead of `plant.id`.
- `app/myGarden/page.tsx`: the table footer total is hardcoded to `$2,500.00`.
- `app/layout.tsx`: metadata description is still `Generated by create next app`.
